\textbf{Protocol.}
Dataset \texttt{dense\_i1} ($N{=}38$ nodes, $F{=}27$ features, 15 supervised devices: 7 machines, 4 gantries, 4 AGVs);
episode split $140/28/36$ (seed 42); test windows 5354.
Input $T_{\mathrm{in}}{=}30$\,min, horizon $H{=}20$\,min, 60\,s windows.
Bottleneck truth: longest bottleneck segment per device within $H$; new bottlenecks must last $\ge 8$\,min (Min8), ongoing ones $\ge 1$\,min;
start cap $\le 5/10/15$\,min selects which events count as positives.
A report is correct iff the device matches and $|\hat{s}-s|\le 3$\,min.
Thresholds are selected on validation with report precision $\ge 0.80$, then frozen on test (0.94 for most runs).

\textbf{Sources.}
Event reports, cause head, remaining time and occupancy grid come from each run's \texttt{last\_metrics.json} (test split, selected checkpoint).
Duration / start MAE and RMSE, state F1 and per-device numbers come from \texttt{factory\_bn/eval\_bottleneck.py}; its will15 F1 reproduces the training report for all 33 runs that have one.

\textbf{Arms.}
\textbf{BestModel} = Full-S1 + remaining-time head fine-tuning (encoder and all bottleneck / cause heads frozen), so its bottleneck and cause numbers equal Full-S1 and only remaining time changes.
Ablations remove one component and, except NoFarBoost, are trained from scratch for 50 epochs (BestModel: warm start + curriculum, 100 epochs), so deltas mix component removal with training budget.

\textbf{Metric groups.}
(i) bottleneck prediction: who / when / how long (Tables 1--3);
(ii) bottleneck cause: process-heuristic cause classification (Table 4);
(iii) order remaining time (Table 5).
